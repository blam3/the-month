# Verified export contract

The demo exports only decision and expense rows, not instruction/ending screens.
The bundled timeline has 15 decisions and 6 expenses. Every ledger row records
`event_id`, `trial_role`, `balance_before`, `delta`, `balance_after`, `seed`,
`session_id`, `demo_only`, `schema_version`, and `plugin_version`, alongside the
jsPsych timing/trial fields. The identity is:

`balance_after = balance_before + delta`

The next row's `balance_before` equals the previous `balance_after`. Expense
rows total -1450 model dollars across the six scripted bills. This is not an
actual payment experiment. Initial balance is 1000; winnings can increase it.

Decision rows also record displayed `response` index, `chosen_tag`, `chosen_p`,
`chosen_win`, `chosen_lose`, `delta`, `outcome_won`, `option_order`, and
`options_json`. Decode `options_json` as JSON to reconstruct the displayed options.
`chose_risky` records stochastic resolution, including ambiguous options;
`chose_ambiguous` records hidden displayed odds. These flags can overlap.
At p=0 or p=1 the outcome is deterministic and `outcome_won` is null.

CSV uses quoted fields, including escaped JSON; use a real CSV reader instead
of splitting on commas. JSON preserves booleans and nulls. CSV represents values
as text (null/absent fields may be empty). Only the ledger columns are shared
across both event types; decision fields are absent/empty for expenses.

The [committed export](../examples/exports/demo.csv),
[JSON](../examples/exports/demo.json), and
[verification report](../examples/exports/verification.json) were generated by
an automated browser selecting the first displayed option with seed
`verified-demo`. They are software-test fixtures, not participant data. Response
times reflect automation. Replay checks exclude timing/session-ID fields.

Files are created in the browser and downloaded on request; there is no upload
endpoint. Hosting infrastructure still serves the page and assets. This demo
does not provide consent, participant identity, secure collection, or a data
retention system for an actual study.
